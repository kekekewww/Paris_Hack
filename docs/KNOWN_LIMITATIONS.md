本輪語意模式會外送必要的當前訊息與最多8則歷史，合計最多9則／6000字；當前訊息須為1–4000字，遮罩後完整保留。歷史user每則最多1000字、assistant最多600字，超長只保留完整句段，無安全句段則排除。保留最後安全引導回覆與「有／沒有／是／不是」短答所需的前一個結構化追問；必要問句未能完整保留遮罩後內容（包含被上限縮減）時，短答一併排除。文件、answer、uncertain及不明配對不納入，所以不能保證模型記得所有舊內容。明顯識別資料先做盡力遮罩，不是全面去識別；使用者自行輸入的事故、就醫與個人文字可能仍含未匹配敏感資訊，不應誤稱為所有醫療資訊皆不外送。語意請求另外帶已確認類型、準備條件與最小details（關係、診斷／術名、部分日期、商品碼／版本）及dialogue_state草稿／待答問題（剔除active_proposal）；6000字僅限對話本身，摘要另外計入請求。新增欄位亦檢查明顯識別資料／憑證，但不是完整去識別；不帶官方evidence，也不自動附加原始上傳檔、OCR／抽取全文、分析欄位或完整案件物件。模型只提出語意提案；文件要求由伺服器決定，新案件由使用者確認後才寫入；已建案可提出結構化差異，使用者以有效proposal_id及revision明確確認後才更新；過期、跨案及已用提案拒絕。有依據的文件問答仍只允許模型選官方證據ID，不讓模型自由生成規範或URL；未知子題明示資料不足。`store:false` 等參數不代表供應商保留政策已查核。

目前可填六項準備條件，三項常用條件優先呈現，其餘可展開；未回答者保留 `unknown` 與人工確認。進度計入自行備妥及確認不適用項目，因此不是 OCR 通過率，更不是理賠審核進度。

## OCR 與預覽

- 接受有效 PDF、JPG、PNG；單檔最多 10 MB、PDF 最多 10 頁、圖片最多 2,000 萬像素。不支援加密 PDF、動畫圖片、Office 檔或批次上傳。
- PyMuPDF 擷取文字，RapidOCR 處理圖片與掃描頁。模型依賴未安裝或解碼失敗時會回錯誤，不產生模擬成功。
- 清晰度不足頁先以實際影像量測判為需重傳，不強行辨識。全部跳過時 provider 為 `quality_precheck`，明示未執行 OCR、不提供欄位判讀；混合文件只讀取可處理頁，整體仍 uncertain。這是工程品質預檢，不是官方規定或理賠核准。
- `application` 支援VIE_Claim.2024.01版本與可靠標籤／條件檢查，含中央基本欄位、付款、稅務選項與續頁；沒有原版像素校準或全面手寫辨識。未知版本會明示uncertain，不驗姓名、證號或保單真實性，也不保證每處空白必須填寫。PDF內嵌圖片亦有單張／每頁總來源2,000萬像素上限。
- 模糊、反光、手寫、傾斜、多欄、文字順序或字形差異可能造成漏字與誤判。信心分數不是經校準的正確率；沒有疑點也不能代替人工核對。
- 簽名一律人工確認，不驗真、辨識本人性或判斷法律效力。其他文件僅抽字並要求人工核對。合成申請書仍保留簽名／人工覆核提醒；使用者完成核對後另可標manual_ready，原OCR缺漏及覆核旗標保留，不變成審核通過。
- 找不到可靠欄位標籤時不顯示精確框，保留`unlocated`文字提醒；品質提示標為`page`，不是精確缺漏定位。頂層框線只列可靠`label`定位，UI以finding自身ID對應，不以陣列索引猜位置。預覽與分析都需對照原件。
- 原件只用於解析及同分頁暫時預覽；受限快取最多30MB、單檔10MB，依案件／文件／分析版本及SHA256匹配。關閉再開視窗可使用仍在快取中的同一原件；遭容量淘汰、重新整理或關閉分頁後須重選。原件不落SQLite、localStorage或sessionStorage，不是可重新下載的文件庫。

## 保存、隱私與安全

案件以 cookie owner 隔離，沒有正式登入、跨裝置同步、帳號找回或角色權限。清除 cookie 後不能恢復同一 owner 的案件；瀏覽器只記錄目前案件 ID，不提供所有案件列表。每 owner 最多 20 件，每案最多 100 回成功對話。

API案件建立後固定24小時到期；本機SQLite在讀寫及每300秒背景清理。Cloudflare遠端模式使用獨立SQLite Durable Object，在每次操作與排程alarm清理，與Container磁碟／重啟分離；每owner20案與到期不可存取語意相同。原始檔與抽取全文不寫入案件庫，仍保存使用者對話、條件、details、dialogue_state、檔名與結構化分析，可能含敏感資訊。TTL／刪案不能保證平台備份、Time Travel或物理儲存立即抹除，也不是正式資安稽核或額外的應用層靜態加密。只用合成資料，展示後清除案件。

未設定 `CASE_STORE_URL`／`CASE_STORE_TOKEN` 時使用原本本機SQLite；任一非空就選HTTPCaseStore，兩者須同時有效，僅接受自己的HTTPS `*.workers.dev/__internal/cases`，未開放自訂網域儲存位址。內部token由Worker secret注入，與模型key分開，不放URL、Git或前端。配置不完整會啟動失敗，遠端不可用明確回503，不回退容器暫存磁碟。單次內部命令最多1MiB；冗長案件可能在單案100回對話上限前先達儲存大小限制。

Mock 案件在分頁 `sessionStorage`，與 API 的保存機制不同。下載的摘要離開系統管理範圍，應自行妥善保管。

目前來源白名單、輸入驗證、提示注入邊界、安全標頭及速率限制是原型防護。速率限制按每程序的連線 IP 計算，不是跨程序集中配額，也不信任任意轉送 IP 標頭。這不等同正式保險服務資安驗收。

本版仍以單一Uvicorn worker、單一app副本執行，`--workers`只能設1，Cloudflare亦只設定一個Container。128把案件非同步鎖、對話工作與速率限制僅在同程序生效；本機SQLite尚無跨程序版本比對。遠端SQLite Durable Object新增原子revision／CAS，衝突回409 `CASE_CONFLICT`，沒有自動合併，但CAS不等於對話工作與配額已可水平擴充；未完成跨程序協調及集中速率限制前仍不可增加副本。

## 逾時與故障恢復

HTTP adapter 一般操作預設 15 秒逾時，對話整體330秒，文件分析另設95秒；後端對話／分析上限分別為310／90秒。網路中斷、逾時或首次 OCR 初始化等情況，不保證立即終止已開始的 CPU OCR；後端也可能已保存結果但回應未送達。請先等候並重新整理檢查已保存結果，確認狀態後再重試，避免重複處理。

OpenRouter外部請求使用 `LLM_TIMEOUT_SECONDS=300`，預設及最高五分鐘，後端310秒、前端330秒；背景工作以短HTTP請求查詢，避開展示代理的單次等待上限。[長等待說明](LLM_WAIT.md)。工作狀態只存目前單程序記憶體，重啟會清除；重新整理會停止該分頁的查詢，已完成回覆可由案件恢復。同案未完成時拒絕另一個送出；刪案取消本機工作並禁止晚寫回，不保證供應商已停止生成。單次工作區「…」診斷曾出現cost0、completion1800、finishlength而被拒；語意cap4096只針對這項上限，官方證據仍1800。另一次4096工作區探測雖stop／cost0，仍因事實來源驗證失敗被拒，不能推論所有INVALID、截斷或限流已修復。免費供應商的等待、推論與回覆仍可能超出五分鐘；限流或逾時只明確顯示可重試錯誤，不增加自動重試、備援模型或費用。環境金鑰模式的 `llm_verified` 保留先前成功紀錄，Runtime模式不保留且一律false；兩者都不能當作重試必定成功的依據。

最終容器實測首次圖片 OCR 曾超出內部 45 秒預算，明確回 `503 OCR_TIMEOUT`；模型載入後同一完整 smoke 重試 39 項通過。預算包含模型匯入、ONNX 初始化、圖最佳化與推論，但沒有分階段計時，不能斷定哪個步驟耗盡預算。Health 只確認 HTTP 與套件存在，不代表圖片 OCR 已暖機；展示前使用合成 smoke 驗證。尚未提供啟動預載／模型 readiness 或程序硬中止，這是目前可靠性邊界。

前輪 OpenRouter 整合的完整後端測試亦曾出現 OCR `bad allocation`。該單項重驗與最終293項後端測試通過，但沒有根因已定位或修復的證據，不能宣稱記憶體配置問題已根治；保留為可靠性限制，展示前仍須以合成文件實際確認。

官方文件在新分頁開啟；外部下載失敗時不能由本機確認官網故障原因，也不會自動更換未查核網址。應保留原有來源與準備狀態，回官方入口核對。受控故障的重現步驟見 [Demo 的 G、H 情境](DEMO.md)。

# 已知限制

更新日期：2026-10-17（臺灣）。本文記錄目前功能邊界；Phase 2、Phase 3 與部署驗收狀態請以 [STATUS.md](../STATUS.md) 及實際測試報告為準。

## 服務與 AI

| 項目 | 目前能力與限制 |
|---|---|
| Mock | 可完整操作前端；對話、分析與框線為固定模擬情境，不能證明真實 AI 或 OCR 已完成 |
| API | 使用 FastAPI、SQLite、本機官方資料及實際文件分析；失敗會顯示錯誤，不回退 Mock |
| `grounded_rules` | 實際執行中文詞彙檢索與規則，`is_simulated=false`；不是生成式 LLM，`llm_configured=false` |
| 外部 LLM | 已實作可選 `openai_compatible` Adapter，只有離線 HTTP transport 驗證；未驗證真實模型請求，Phase 2 真實 LLM 驗收仍為 BLOCKED |
| 語言理解 | 以保守規則辨識三類就醫描述、否定與不確定詞；複雜語意、混合事件或未涵蓋說法仍可能誤判，須由使用者確認類別 |
| 檢索 | 小型本機中文詞彙索引，沒有向量資料庫；預設規則直接回覆，外部模式也只可整理既有證據。查無支持內容不代表官網不存在該資訊 |

外部模式須明確設定 `LLM_PROVIDER=openai_compatible`。後端 `LLM_BASE_URL` 預設 `https://api.openai.com/v1`，`LLM_API_KEY` 與 `LLM_MODEL` 無預設且必填；範本仍維持本機模式及空白 key／model。缺設定回 `503 / LLM_NOT_CONFIGURED`，設定不合法、網路或輸出驗證失敗也回明確錯誤，不以本機／Mock 回覆掩蓋外部失敗。

即使外部設定齊全，健康檢查的 `llm_configured=true` 也只代表設定齊備。本版 `llm_verified` 固定為 `false`，健康檢查不送出外部請求；不能據此宣稱憑證有效、模型可用或真實整合驗收完成。詳見 [LLM 整合紀錄](LLM_INTEGRATION.md)。

外部模型只接收本次檢索證據的標題、完整段落、來源 ID 與頁碼，不接收原始上傳文件、案件、使用者問題或對話歷史。只有有依據的準備回答會走外部 Adapter，分類與條件提案等仍由規則處理。輸出只允許原樣選取完整證據，尚未提供自由改寫的語意事實查核；`store:false` 請求參數也不代表供應商保留政策已查核。

## 官方資料與文件要求

目前支援住院醫療、醫療門診、防癌或重大疾病。公開文件只提供準備規則，不能證明個別保單的保障、資格、疾病定義或金額。助手不連會員、保單、保險公司內部系統，也不提交理賠。

來源以 [2026-10-17 查核紀錄](OFFICIAL_SOURCES.md) 為基準，執行期不會自動重新下載或監測異動；官方連結當日可讀不保證之後持續可用。官網與表單的收據正副本、病理報告、授權範圍等差異仍需官方確認。版本未知維持未標明，不以網址參數推定版本。

部分進階條件未在目前表單逐一詢問，會保留 `unknown` 與人工確認。進度計入自行備妥及確認不適用項目，因此不是 OCR 通過率，更不是理賠審核進度。

## OCR 與預覽

- 接受有效 PDF、JPG、PNG；單檔最多 10 MB、PDF 最多 10 頁、圖片最多 2,000 萬像素。不支援加密 PDF、動畫圖片、Office 檔或批次上傳。
- PyMuPDF 擷取文字，RapidOCR 處理圖片與掃描頁。模型依賴未安裝或解碼失敗時會回錯誤，不產生模擬成功。
- 清晰度不足頁先以實際影像量測判為需重傳，不強行辨識。全部跳過時 provider 為 `quality_precheck`，明示未執行 OCR、不提供欄位判讀；混合文件只讀取可處理頁，整體仍 uncertain。這是工程品質預檢，不是官方規定或理賠核准。
- 只有 `application` 項目檢查指定的五個文字欄位；不驗證姓名、身分證字號或保單的真實性，不涵蓋全部表單欄位、附件頁及所有排版。
- 模糊、反光、手寫、傾斜、多欄、文字順序或字形差異可能造成漏字與誤判。信心分數不是經校準的正確率；沒有疑點也不能代替人工核對。
- 簽名一律人工確認，不驗真、辨識本人性或判斷法律效力。其他文件僅抽字並要求人工核對。完整合成申請書仍會保留簽名提醒與 `needs_attention`。
- 找不到欄位時，框線可能使用預設提示區，不能當成缺漏的精確位置。預覽與分析都需對照原件。
- 原件只用於本次解析及暫時預覽，不保存為可重新下載的文件。重新整理或重開檢查視窗後，要重新選取原件才能預覽。

## 保存、隱私與安全

案件以 cookie owner 隔離，沒有正式登入、跨裝置同步、帳號找回或角色權限。清除 cookie 後不能恢復同一 owner 的案件；瀏覽器只記錄目前案件 ID，不提供所有案件列表。每 owner 最多 20 件，每案最多 100 回成功對話。

API 案件建立後固定 24 小時到期；到期讀寫會清理，背景清理每 300 秒執行，因此磁碟刪除時間可能略晚於到期。原始檔與抽取全文不寫入案件庫，SQLite 仍保存使用者對話、條件、檔名與結構化結果，可能含敏感資訊；不提供靜態加密、正式稽核或備份抹除保證。請只用合成資料，完成展示後清除案件。

Mock 案件在分頁 `sessionStorage`，與 API 的保存機制不同。下載的摘要離開系統管理範圍，應自行妥善保管。

目前來源白名單、輸入驗證、提示注入邊界、安全標頭及速率限制是原型防護。速率限制按每程序的連線 IP 計算，不是跨程序集中配額，也不信任任意轉送 IP 標頭。這不等同正式保險服務資安驗收。

本版必須以單一 Uvicorn worker、單一 app 副本執行，`--workers` 只能設為 `1`，不可水平擴充。128 把案件非同步鎖只在同一程序內生效，多 worker 的案件讀取、修改與保存可能互相覆蓋，導致更新遺失；頻率限制也會分散計算。擴充前須先加入資料庫版本／CAS 或其他跨程序一致性控制與集中速率限制。

## 逾時與故障恢復

HTTP adapter 一般操作預設 15 秒逾時，對話為 50 秒，文件分析另設 95 秒；後端對話／分析路由上限分別為 45／90 秒。網路中斷、逾時或首次 OCR 初始化等情況，不保證立即終止已開始的 CPU OCR；後端也可能已保存結果但回應未送達。請先等候並重新整理檢查已保存結果，確認狀態後再重試，避免重複處理。

最終容器實測首次圖片 OCR 曾超出內部 45 秒預算，明確回 `503 OCR_TIMEOUT`；模型載入後同一完整 smoke 重試 39 項通過。預算包含模型匯入、ONNX 初始化、圖最佳化與推論，但沒有分階段計時，不能斷定哪個步驟耗盡預算。Health 只確認 HTTP 與套件存在，不代表圖片 OCR 已暖機；展示前使用合成 smoke 驗證。尚未提供啟動預載／模型 readiness 或程序硬中止，這是目前可靠性邊界。

官方文件在新分頁開啟；外部下載失敗時不能由本機確認官網故障原因，也不會自動更換未查核網址。應保留原有來源與準備狀態，回官方入口核對。受控故障的重現步驟見 [Demo 的 G、H 情境](DEMO.md)。

## 部署與驗收

Docker 設定準備、靜態解析、實際 image build、容器啟動及公開 HTTPS 是不同驗證項目，須分別留下結果。外部部署帳號、DNS、TLS 與授權尚未由文件本身證實；不得因設定存在便宣稱公開網站已部署。映像只包含執行需要的前端、後端與官方索引，合成展示文件保留在原始專案 `demo/documents/`。

真實外部 LLM 與正式外部部署仍是交付依賴；未通過的驗收不得以 Mock、攔截回覆或本機測試代替。
